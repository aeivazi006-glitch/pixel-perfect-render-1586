## Base44 dev environment

Run everything through `docker-compose.base44.yml` — do not add a `.env` file and do
not run the repo's own build/publish flow for local work:

```sh
docker compose -f docker-compose.base44.yml up -d      # first boot, or after compose/dependency changes
docker compose -f docker-compose.base44.yml logs -f web
```

Non-obvious notes:

- **Runtime is Bun**, not npm, even though the README says npm. `bun.lock` + `bunfig.toml`
  are authoritative and `bun install --frozen-lockfile` runs at container start into the
  `web_node_modules` volume. Never run a second installer against that volume; stop the
  `web` service first if you must.
- **No backend, database or credentials.** This is a visual prototype: the catalog,
  categories, ideas and footer link data are static demo content in `src/data/techverse.ts`.
  There is nothing to migrate or seed.
- **Product/editorial photography is remote** (`images.unsplash.com`) and resolves in the
  browser, so the preview needs outbound network. Keep image URLs as full remote URLs when
  adding imagery.
- **File-based routing**: `src/routeTree.gen.ts` is regenerated by the TanStack Router Vite
  plugin whenever files in `src/routes/` change — never edit it by hand. After adding or
  deleting a route, expect one full page reload (HMR restarts the SSR module graph).
- **Verifying it works**: `curl -sf http://localhost:3000/ | grep -a "TechVerse"`. Use
  `grep -a` — the SSR payload contains bytes that make grep treat it as binary.
